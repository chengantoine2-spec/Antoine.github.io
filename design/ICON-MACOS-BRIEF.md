## 1. 现在这套图标差在哪（我读了代码与全部图标文件之后的判断）

> 下面每条都带**文件与行号**，你可以逐条复核。**不是"我觉得"，是量出来的。**

### (a) 尺寸跨度 12px → 64px，而单一 24 网格 + 1.6 线宽**服务不了两端**（最根本的问题）

实测调用点（读代码得到，不是推测）：

| 出现在哪 | 调用处 | **实际渲染尺寸** |
|---|---|---|
| 窗口标签行 | `src/components/desktop/FrameTabs.tsx:169`（`h-3 w-3`） | **12px** |
| 顶部菜单栏（「所有项目」/「位置」） | `src/components/desktop/MenuBar.tsx:204`、`:246`（`h-3.5 w-3.5`） | **14px** |
| 开始菜单每一行 | `src/components/desktop/StartMenu.tsx:66`（`h-4 w-4`） | 16px |
| 位置菜单 / 设置窗口 | `DockPositionMenu.tsx:56`、`program/SettingsWindow.tsx:237`（`h-4 w-4`） | 16px |
| **Dock 图标** | `Dock.tsx:790`（`appGlyph(app.id, 'h-1/2 w-1/2')`）+ `Dock.tsx:179`（按钮 `clamp(iconSize, 32, 64)`） | **16 ~ 32px**（默认 40px 按钮 → **只有 20px**） |
| Dock 拖拽幽灵 | `Dock.tsx:944`（`h-full w-full`） | 32 ~ 64px（放大后更大） |
| DSH 窗口说明卡 | `program/DshWindow.tsx:354`（`h-8 w-8`） | 32px |
| 标题栏「最大化 / 还原」 | `glyphs/MaximizeGlyph.tsx`（默认 `h-3 w-3`） | 12px |
| 菜单栏全屏按钮 | `desktop/FullscreenButton.tsx:49`（字形默认 `h-1/2 w-1/2`） | ≈14px |

**算一下线宽的物理值**（24 网格、`strokeWidth 1.6`，见 `icons/base.ts`）：

| 渲染尺寸 | 1.6 折合实际笔画 |
|---|---|
| **12px** | **0.80px** ← 亚像素，抗锯齿后糊成灰点，细节全丢 |
| 14px | 0.93px |
| 16px | 1.07px |
| 20px | 1.33px |
| 32px | 2.13px |
| 64px | **4.27px** ← 反过来偏粗、显得笨 |

对比：**macOS 的 SF Symbols 是按尺寸给不同字重的**（同一个符号在 13pt 与 24pt 下不是同一套笔画比例）。
这正是"一套 24 网格 + 单一 1.6"做不到的事。
**→ 你要给出取舍方案**（见第 5 节「方案 A / B / C」），并说明各自在 12px 与 64px 两端的代价。

### (b) **Dock 图标的实际渲染尺寸只有按钮的一半** —— 与 macOS 差距最大的单点

`Dock.tsx:790` 传的是 `h-1/2 w-1/2`（**按钮的一半**），而 macOS 的 Dock 图标几乎**填满**格子。
所以默认 40px 按钮里，我们的图标**只有 20px**，周围一圈空 —— 这是"看着不像 macOS"最直观的一条。

⚠️ **这一条的主修在主管手里**（填充比例属于外壳，`Dock.tsx` 归我）。你这边只需要：
**保证 20px 下能认出来**（我会同步把填充比例调大，两者要一起看效果）。

### (c) Dock 底板是**半透明毛玻璃**，单色细线压上去对比度不稳

`tokens.css` 里 Dock 底板：浅色 `rgba(255,255,255,.2)` / 深色 `rgba(28,28,30,.35)` + `blur 40px`，
**壁纸会透过来**（浅色壁纸是冷蓝渐变，深色是近黑渐变）。而图标是**单色线稿**（`currentColor`）。
macOS 的应用图标自带 squircle 底色，**我们的没有** —— 所以：

- 必须保证在 **两套主题 × 两种底色（纯 surface 与毛玻璃底）** 下都清楚；
- 图形类对比度目标：**≥ 3:1 是底线，建议 ≥ 4.5:1**（和交通灯那条断言同一口径，`verify.mjs` 里有先例）；
- **不建议**给图标外挂一层底板/白描边（那会让 12/14px 档更糊）；**先靠"加粗 + 留白 + 减少细节"解决**。
  若你实测仍然糊，把带底板的方案做成对照页里的 B 方案给我看，由我决定。

### (d) 「选中 / 未选中 / 禁用」三态**没有定义**

现在换色**全在外层**（`text-chrome-ink` / `text-accent-ink` / `text-accent`，见 `StartMenu.tsx:66`、
`FrameTabs.tsx:169`、`Dock.tsx` 的按钮类），**禁用态根本没有**。
**要求**：图标**只画一种**（不自带颜色变体、不画灰版），禁用由外层 `opacity` 表达；
请给出你建议的禁用不透明度（参考区间 **0.35 ~ 0.45**）写进你的交付说明，我按它加类。

### (e) 现在有**两套网格 + 两套线宽 + 第三种填充**（这是**有意**的，但要你判断保不保）

| 体系 | 谁 | 网格 / 线宽 | 为什么 |
|---|---|---|---|
| A | 12 个应用图标（`icons/*Icon.tsx`） | **24 网格 / 1.6** | 主体系（`base.ts` 的 `iconBase()`） |
| B | `FullscreenGlyph` / `MaximizeGlyph` / `PositionGlyph` | **12 网格 / 1.2** | 画在很小的按钮里，**相对线宽必须更粗**，视觉重量才齐 —— 理由与踩坑写在 `PositionGlyph.tsx` 顶部注释里（历史：曾经是 24 网格/1.4，并排站在任务栏上比全屏字形细一半） |
| C | `MenuGlyph` | 24 网格，但**纯 fill** 九宫格 | 唯一的实心用法 |

**你要做的判断**：统一到 24 网格（更省心、更"一家人"）**还是**保留两套（小尺寸更清楚）。
两条都接受，但**必须在文件头把理由写清**，并用第 4 节的对照页证明"14px 下不比现在差"。
⚠️ 硬约束：**`verify.mjs` 会数最大化简形里的图形元素个数并断言 `=== 2`** —— 还原态**必须保持两个图形**
（两个方块 / 一个方块+一条线都行，**别变成三个**）。

### (f) 视觉重心与墨量不齐

信封（`contact`）、五角星（`skills`）、实心九宫格（`MenuGlyph`）、屏幕+提示符（`terminal`）四种密度混在一排里，
墨量差得比较明显（上一版任务书也点了这条，说明**当时没解决**）。方法：**缩略图排一排、眯眼看**，
再逐个做**光学居中**（圆形的略放大、尖角的略收）。

### (g) **新成员：塔罗牌图标已进仓库，必须一起统一**

当前工作区已经出现 `src/components/icons/TarotIcon.tsx`，并且 `ICON_SET.tarot` 已经登记
（**是另一个 agent 在加「塔罗牌」窗口时做的**）。它的母题是"牌 + 四角星 + 月牙"，**密度偏满**，
是这一轮统一时最好的对照样本：它必须和其它 11 个看起来像同一个人的手笔。
它**符合** `iconBase()` 契约（我核对过），但**线条密度与留白和现有这套不齐**。

## 3. 硬约束（违反就上线不了）

1. **不许改 `ICON_SET` 的键名**（`src/components/icons/index.ts`）：`apps.ts` 的 `icon`、路由、任务栏、
   两个验证脚本都挂在上面。现在是 **12 个键**：
   `about` / `projects` / `blog` / `write` / `skills` / `contact` / `terminal` / `assets` / `settings` / `wiki` / `dsh` / `tarot`。
   要加新图标位 → **先找我改 `IconName`**。
2. **不许改任何 `aria-label`**：`verify.mjs`（**当前 122 项**）与 `verify-dst.mjs`（**21 项**）靠
   `button[aria-label="博客"]` 这类选择器点任务栏。图标自己保持 `aria-hidden`（`iconBase()` 已给），
   **不要**在 SVG 里加 `<title>`。
3. **原创 SVG，零素材**：**不许**从 `playground-macos` / `macos-web` / `daedalOS` / `win11React` /
   `react-osx-dock` 等参考项目里复制 **SVG / 图标字体 / 壁纸 / 截图**。
   ⚠️ MIT 只覆盖"作者写的代码"，**不覆盖它们夹带的第三方素材**；**Apple 的系统图标与壁纸是版权物，绝对不能用**。
   （原话见 `MACOS-BRIEF.md` 第 5 节「版权红线」。）参考项目**只能看数值与做法**，不能取素材、也不能把它们的
   截图放进仓库。
4. **只用 `currentColor`**：组件里不许出现 `#fff` / `rgb()` / 具名色 / `stroke="#333"`。写死 = 换主题时那个图标不变色，直接不合格。允许在该元素上写 `fill="currentColor"`（如 `MenuGlyph` / `PositionGlyph` 的做法）。
5. **不引依赖**：图标库、icon font、SVG 优化器、构建插件一律不行（项目规矩：新增依赖要站主批准 + 登记）。
6. **不许改验证脚本**；不要为了让套件变绿去迁就实现。
7. `public/logo.svg`（焦糖布丁站标）**不动**。
8. 改完必须 `npm run typecheck && npm run build` 通过；涉及外观的改动要说明**哪些断言可能受影响**
   （例如你动了字形的图形个数、或改了尺寸相关的类名）。
9. 文件契约照旧（`icons/base.ts`）：`viewBox="0 0 24 24"`（或统一后的新网格，见 1(e)）、
   组件签名固定 `{ className }: IconProps`、**不写死 `width`/`height` 属性**（要靠 `className` 缩放）、
   内容大致画在 3~21 之间（留 1.5px 视觉边距）。
10. **文档不许自相矛盾**：你改动后如果某一版说明过时了，**同一批改掉**（这个仓库吃过这个亏）。

## 8. 什么时候来找我（主管）

- 想加 `IconName` / 想改外壳里图标的**尺寸或填充比例** → 找我（我改 `types/desktop.ts` 与 `Dock.tsx`）。
- 想给图标组件**加 props**（比如 `size` 变体的 B 方案）→ 先问我：`AppIcon` 是唯一调用入口，
  加 props 要连它和调用点一起改。
- 想改 `icons/base.ts` 的全局几何（网格/线宽）→ **可以**，但要在回复里说明影响面（全套一起变），
  并让第 4 节的对照页证明两端都不亏。
- 想动站标、想加依赖、想改验证脚本 → 基本会被拒，除非站主点头。
